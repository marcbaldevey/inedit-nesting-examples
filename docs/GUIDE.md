# Inèdit nesting editor — integration guide

This guide explains how to put the nesting editor in a web application: loading it, giving it images and
parameters, reading the result as JSON, generating the print PDF through Inèdit Connect, and adapting its
look and language.

Two working pages show it in use: [`examples/minimal`](../examples/minimal), the simplest set-up, and [`examples/basic`](../examples/basic), which uses every feature described here (see [The examples](#15-the-examples)).

## 1. How it works

```
 Your web page                                   Inèdit Connect (only for the PDF)
┌──────────────────────────────────────────┐    ┌──────────────────────────────────┐
│ items (images + sizes) ─┐                │    │ POST /api/nestings/render/files  │
│ parameters ─────────────┼─► NestingEditor│───►│ POST /api/nestings/render        │
│                         │   (browser)    │    │ GET  /api/nestings/render/:id    │
│ ◄── NestingDocument (JSON) ─┘            │◄───│   → signed link to the PDF       │
└──────────────────────────────────────────┘    └──────────────────────────────────┘
```

- **Nesting happens in the browser.** The editor places the pieces in a Web Worker, traces the silhouettes of the
  images itself and lets the user adjust the result. No server is involved, and nothing is uploaded, until a PDF is requested.
- **The result is a JSON document** (`NestingDocument`) that references your items by your own identifiers (`ref`),
  never by Inèdit Connect ids. You can store it, send it to your own backend, or reload it later.
- **The print PDF is generated by Inèdit Connect**, with the same code that renders the nests saved inside Inèdit Connect.
  The editor uploads the artwork, queues the PDF and gets back a download link. This needs an Inèdit Connect access token.

The editor is plain TypeScript compiled to JavaScript. It has no dependencies and works with any framework or none.

## 2. Requirements

- A current browser: Chrome, Edge, Firefox or Safari from the last two years. The editor uses Web Workers, canvas,
  `ResizeObserver`, CSS container queries and `color-mix()`.
- For the PDF: an Inèdit Connect account and an access token (see [section 11](#11-generating-the-pdf-with-inèdit-connect)).

If the page's content security policy forbids `blob:` workers, the editor computes on the main thread instead.
It still works, but the page may freeze for a moment on large nests.

## 3. Installation

Each version is published as these files:

| File | Use it for |
|---|---|
| `nesting.global.js` | A plain `<script>` tag. Defines `window.IneditNesting`. |
| `nesting.js` | ES module: bundlers (Vite, webpack…) and `<script type="module">`. |
| `nesting.umd.cjs` | `require()` in CommonJS tool chains. |
| `nesting.css` | Default styles. Always load it, unless you write your own (see [Styling](#12-styling)). |
| `*.d.ts` | TypeScript types. |

### With a `<script>` tag (no build step)

```html
<link rel="stylesheet" href="https://nreservice.inedit.com/api/static/nesting/0.1.2/nesting.css" />
<script src="https://nreservice.inedit.com/api/static/nesting/0.1.2/nesting.global.js"></script>
<script>
  const { NestingEditor } = window.IneditNesting;
</script>
```

The files are served by Inèdit Connect (`nreservice.inedit.com`), the same server whose API generates the PDF. They are
public (no token) and never change once published, so browsers cache them for a year. Every URL names an exact version:
an update never changes a live page by surprise, and you move to a new version by changing the number.

The ES module loads the same way from a `<script type="module">`:

```html
<script type="module">
  import { NestingEditor } from "https://nreservice.inedit.com/api/static/nesting/0.1.2/nesting.js";
</script>
```

### With npm and a bundler

Each version is also published as npm packages, at the same address. Install from the URL:

```sh
npm install https://nreservice.inedit.com/api/static/nesting/0.1.2/inedit-nesting-ui-0.1.2.tgz
# pnpm add … and yarn add … take the same URL
```

```js
import { NestingEditor } from "@inedit/nesting-ui";
import "@inedit/nesting-ui/nesting.css";
```

`package.json` records the URL, so the version stays pinned; to update, install the URL of the new version. `npm update`
and version ranges (`^0.1.0`) do not apply to URL installs.

`@inedit/nesting-core` (nesting without the user interface, see [section 10](#10-exporting-the-nest-as-json)) is installed
along with the editor, or on its own from `…/0.1.2/inedit-nesting-core-0.1.2.tgz`.

For Vue 3 there is a ready-made component, `@inedit/nesting-vue`, at `…/0.1.2/inedit-nesting-vue-0.1.2.tgz`
(it brings the editor along; see [Vue 3](#vue-3)).

## 4. Quick start

```html
<div id="nesting" style="height: 700px"></div>

<script>
  const editor = new IneditNesting.NestingEditor("#nesting", {
    page: { width: 1.6, units: "m" },
    options: { mode: "trueShape", allowRotation: true, allowOrthogonalRotation: true, padding: 5, paddingUnits: "mm" },
    items: [
      { ref: "logo", name: "Logo", image: "/images/logo.png", width: 20, units: "cm", copies: 10 },
      { ref: "flag", name: "Flag", image: fileInput.files[0], width: 60, length: 40, units: "cm" },
    ],
  });

  editor.on("change", ({ document }) => {
    // document is the NestingDocument, or null while there is nothing valid to show
    console.log(document);
  });
</script>
```

The editor fills the element you give it. **Give that element a height**: the editor takes 100% of it, with a minimum of 420 px.

## 5. Configuration reference

```ts
new NestingEditor(target: HTMLElement | string, config: NestingEditorConfig)
```

`target` is an element or a CSS selector. `config` has these fields:

| Field | Type | Required | Description |
|---|---|---|---|
| `page` | `NestingPage` | yes | Page (roll) size. See [section 7](#7-nesting-parameters). |
| `options` | `Partial<NestingOptions>` | no | Nesting parameters. Missing ones take the defaults in [section 7](#7-nesting-parameters). |
| `items` | `NestingEditorItem[]` | no | What to nest. See [section 6](#6-items-and-images). Can also be set later with `setItems()`. |
| `locale` | string | no | Language of the editor: `"en"` (default), `"ca"`, `"es"`, or any language you add. See [section 13](#13-languages-and-texts). |
| `messages` | object | no | Your own texts, replacing built-in ones of that language. See [section 13](#13-languages-and-texts). |
| `ui` | object | no | Interface settings, below. |
| `render` | `RenderConfig` | no | Inèdit Connect connection for the PDF. Without it there is no PDF button. See [section 11](#11-generating-the-pdf-with-inèdit-connect). |
| `timeBudgetMs` | number | no | How long the editor searches for a shorter nest each time it computes. Default `2500`. |

`ui`:

| Field | Default | Description |
|---|---|---|
| `editable` | `true` | `false` shows the nest read-only: no dragging, no rotating, panel controls disabled. |
| `panel` | `true` | `false` hides the side panel. Your page then provides the controls through the API. |
| `controls` | all | Which panel controls to show: any of `"page"`, `"mode"`, `"rotation"`, `"padding"`, `"bleed"`, `"cutLines"`, `"order"`, `"recompute"`, `"export"`, `"pdf"`. `"pdf"` only appears when `render` is set. |
| `theme` | `"light"` | `"dark"` for the dark colour set. |

`page`, `options`, `locale` and `render` are read when the editor is created. Change `page`, `options` and `locale` later
with `setPage()`, `setOptions()` and `setLocale()`. To change `render`, `ui` or `timeBudgetMs`, destroy the editor and create it again.

## 6. Items and images

Each item is one artwork, placed `copies` times.

```ts
type NestingEditorItem = {
  ref: string;              // your identifier, unique among the items
  name?: string;            // shown in the panel, in errors and in the PDF report
  image?: string | Blob;    // URL, data URL, File or Blob
  previewImage?: string | Blob;
  width?: number;           // across the page
  length?: number;          // along the page
  units?: "mm" | "cm" | "m" | "in" | "ft" | "yd" | "pt";  // default: the page unit
  dpi?: number;
  copies?: number;          // default 1
  rotation?: { allowed?: boolean; fixed?: number };
  meta?: unknown;
};
```

### `ref` and `meta`

`ref` identifies the item in everything the editor returns: each placement in the document says which `ref` and
which copy it is. Use your own product, order line or file id. `meta` is any data of yours. It is copied into
the document untouched, so you can put there whatever you need to process the result.

### Giving the image

| `image` value | Shown in the editor | Sent for the PDF |
|---|---|---|
| `File` / `Blob` (e.g. from `<input type="file">`) | yes | uploaded by the editor |
| `"https://…"` URL | yes | Inèdit Connect downloads it (or the editor uploads it with `render.uploadRemoteImages`) |
| Relative URL, `data:` or `blob:` URL | yes | downloaded by the browser and uploaded |

The browser shows PNG, JPEG, WebP, GIF, AVIF and SVG. It cannot show PDF, PSD or TIFF. For those, give the print file
as `image` and a PNG or JPEG rendering of it as `previewImage`: the editor shows and traces `previewImage`,
and Inèdit Connect prints `image`. Inèdit Connect prints PNG, JPEG, TIFF, WebP, PSD (including spot channels)
and PDF (embedded as vector).

An image that cannot be loaded is drawn as a grey box. It still nests, but it needs an explicit size.

### Images from another domain (CORS)

The editor reads the pixels of each image to trace its silhouette for true-shape nesting. For a URL on another
domain the browser only allows that when the server sends CORS headers (`Access-Control-Allow-Origin`).
Without them the image is still shown, but it nests as a rectangle. `File` and `Blob` images never have this problem.

### Size

The physical size is worked out in this order:

1. `width` and `length`: used as given.
2. Only one of them: the other follows the image proportions (`length = width × imageHeight / imageWidth`).
3. Neither, with `dpi`: the image pixels at that resolution (`width = pixels / dpi` inches).
4. None of these: the editor shows an error naming the item and does not nest.

`width` is the size **across** the page and `length` the size **along** it, before any rotation.
A size larger than the page width is an error unless rotation lets the item fit.

### Copies and rotation per item

`copies` places the item that many times. Each copy is a separate piece that can be dragged and rotated on its own.

`rotation` restricts one item, whatever the nest's rotation setting:

- `{ allowed: false }`: every copy stays upright.
- `{ fixed: 90 }`: every copy uses exactly that angle (degrees, clockwise).

### Silhouettes (true-shape mode)

The silhouette is traced from the image (from `previewImage` when given), reduced to 256 px on its longest side:

- **Images with transparency** (at least 1% of transparent pixels): the opaque pixels are the shape.
- **Opaque images**: when at least 60% of the border is one uniform colour, that colour is treated as background,
  filled in from the edges. Enclosed areas of the same colour stay part of the shape.
- Specks smaller than 0.3% of the image are ignored. When the shape covers less than 1% or more than 98.5%
  of the image, the item nests as a rectangle.

So an opaque image whose edge is a solid colour **all the way round** (a coloured label filling the whole image, for example)
has that colour removed. Give such artwork a transparent or white margin, or nest it in rectangular mode.

### Replacing the items

`editor.setItems(items)` replaces all items and nests again. It returns a promise that resolves when the images
are loaded and the nest is computed. Pieces the user pinned or rotated by hand are reset.

## 7. Nesting parameters

### Page

```ts
type NestingPage = {
  width: number;       // fixed size across the page (the roll width)
  units: "mm" | "cm" | "m" | "in" | "ft" | "yd" | "pt";
  maxLength?: number;  // longest acceptable nest, in the same unit
};
```

The page has a fixed width and grows along its length as needed: think of a roll. `maxLength` does not stop the nest
from growing. It draws a red limit line and shows a warning, and `getDocument()` still returns the document. Check
`document.stats.usedLength` against it if you need to refuse longer nests.

### Options

| Option | Default | Description |
|---|---|---|
| `mode` | `"rectangular"` | `"rectangular"` nests bounding boxes; `"trueShape"` nests the silhouettes, so shapes can interlock. |
| `allowRotation` | `true` | Whether pieces may turn. |
| `allowOrthogonalRotation` | `false` | With `allowRotation`: 90° steps instead of only 0°/180°. |
| `rotationStep` | — | With `allowRotation`: every multiple of this many degrees is tried (e.g. `15`). |
| `padding` | `0` | Gap between the cut lines of two pieces. |
| `paddingUnits` | `"mm"` | Unit of `padding`. |
| `bleed` | `0` | Artwork printed beyond the cut line. |
| `bleedUnits` | `"mm"` | Unit of `bleed`. |
| `bleedFill` | `"auto"` | What prints in the bleed: `"auto"` (a PDF's own bleed, otherwise extended edges), `"extend"`, `"mirror"` (rectangles only) or `"none"`. |
| `showCutLines` | `true` | Draw the cut lines in the editor and in the PDF's cut layer. |
| `keepOrder` | `false` | Place items in the given order instead of searching for a shorter nest. |

How the rotation options combine:

| Wanted | `allowRotation` | `allowOrthogonalRotation` | `rotationStep` |
|---|---|---|---|
| No rotation | `false` | – | – |
| 0° and 180° | `true` | `false` | – |
| 0°, 90°, 180°, 270° | `true` | `true` | – |
| Every 15° | `true` | – | `15` |

The space kept between two cut lines is the larger of `padding` and `bleed`, so the bleed of one piece never reaches
the next piece's cut.

Change parameters at any time with `editor.setOptions({ … })` and `editor.setPage({ … })`. Only the fields you pass change.
Changing `showCutLines` or `bleedFill` redraws without nesting again; any other change nests again after a short pause.

## 8. What the user can do in the editor

| Action | Effect |
|---|---|
| Wheel / trackpad scroll | Move the view. Shift + wheel moves sideways. |
| Ctrl/⌘ + wheel, pinch | Zoom around the pointer. |
| Drag the empty page | Move the view. |
| Toolbar buttons | Zoom in, zoom out, fit the nest, fit the page width. |
| Click a piece | Select it. The panel shows its rotation and a "Pinned" switch. |
| Drag a piece | Moves its item to that point in the placement order and nests again ("Keep this order" turns on). |
| Alt + drag a piece | Pins it exactly where it is dropped. The rest is nested around it. Dragging a pinned piece moves it. |
| R / Shift + R | Turn the selected piece +90° / −90°. Its angle is then fixed while the rest is nested again. |
| Escape | Clear the selection. |
| Order list (panel) | Drag rows or use the arrows to change the order; click a row to select its first piece. |

Pinned pieces that overlap are outlined in red and listed in a warning.

## 9. Methods and events

### Methods

| Method | Returns | Description |
|---|---|---|
| `setItems(items)` | `Promise<void>` | Replace the items (see [section 6](#6-items-and-images)). |
| `setOptions(patch)` | – | Change nesting options. |
| `setPage(patch)` | – | Change the page. |
| `recompute()` | `Promise<void>` | Nest again now, and fit the view. |
| `getDocument()` | `NestingDocument \| null` | The current nest, including the user's manual changes. `null` while loading or after an error. |
| `getOptions()` / `getPage()` | object | Current values. |
| `setLocale(locale, messages?)` | – | Switch the language. The nest, the selection and manual changes are kept. |
| `getLocale()` | string | The language in use, after falling back (`"ca"` for `"ca-ES"`, `"en"` for an unknown code). |
| `zoomToFit()` | – | Fit the view to the nest. |
| `generatePdf({ name? })` | `Promise<{ jobId, report, downloadUrl }>` | See [section 11](#11-generating-the-pdf-with-inèdit-connect). |
| `on(event, listener)` | `() => void` | Listen to an event. Call the returned function to stop. |
| `off(event, listener)` | – | Stop listening. |
| `destroy()` | – | Remove the editor from the page and free its worker and images. |

### Events

| Event | Payload | When |
|---|---|---|
| `change` | `{ document: NestingDocument \| null }` | After every nest, manual change or visual option change. `null` when there is nothing valid. |
| `computing` | `{ computing: boolean }` | Nesting starts or ends. |
| `select` | `{ piece: { ref, copy } \| null }` | The selected piece changes. |
| `error` | `{ message, ref? }` | Nesting is impossible (missing size, item wider than the page, image not loaded…). `ref` names the item when known. |
| `pdf-status` | `{ status, error?, jobId?, report? }` | PDF progress: `uploading`, `queued`, `generating`, `ready`, `error`. `error` is in the editor's language (or as the server wrote it); `report` comes with `ready`. |

```js
const stop = editor.on("error", ({ message, ref }) => showToast(message));
// later
stop();
```

## 10. Exporting the nest as JSON

```js
const nestingDocument = editor.getDocument();          // or from the "change" event
await fetch("/my-api/nests", { method: "POST", body: JSON.stringify(nestingDocument) });
```

The panel's "Export JSON" button (control `"export"`) downloads the same document as `nesting.json`.

### The `NestingDocument` format (`inedit.nesting/v1`)

```json
{
  "schema": "inedit.nesting/v1",
  "page": { "width": 1.6, "length": 0.93, "units": "m" },
  "options": {
    "mode": "trueShape", "allowRotation": true, "allowOrthogonalRotation": true,
    "padding": 5, "paddingUnits": "mm", "bleed": 2, "bleedUnits": "mm",
    "bleedFill": "auto", "showCutLines": true, "keepOrder": false
  },
  "items": [
    { "ref": "logo", "name": "Logo", "width": 20, "length": 20, "units": "cm", "copies": 2, "meta": { "sku": "L-20" } }
  ],
  "placements": [
    { "ref": "logo", "copy": 0, "x": 0, "y": 0, "rotation": 0, "width": 0.2, "length": 0.2, "pieceWidth": 0.2, "pieceLength": 0.2 },
    { "ref": "logo", "copy": 1, "x": 0.205, "y": 0, "rotation": 90, "width": 0.2, "length": 0.2, "pieceWidth": 0.2, "pieceLength": 0.2, "locked": true }
  ],
  "stats": { "usedLength": 0.2, "utilization": 0.25 },
  "shapes": { "logo": { "outlines": [[0.1, 0.05, 0.95, 0.5, 0.1, 0.95]], "coverage": 0.43 } }
}
```

| Field | Meaning |
|---|---|
| `page` | Width, length used and unit. All placement values are in this unit. |
| `options` | The parameters the nest was made with. |
| `items` | Your items with their resolved size (a length worked out from the image is filled in) and `meta`. |
| `placements` | One entry per copy. |
| `stats.usedLength` | Length the artwork takes along the page. |
| `stats.utilization` | Share of the used area covered by artwork (0–1). |
| `shapes` | True-shape mode only: each item's silhouette, as closed outlines in image coordinates (0–1, origin top left). |

**Placement coordinates.** `x` runs across the page from the edge shown at the top of the editor, `y` runs along the page from its start.
`x`, `y`, `width` and `length` are the bounding box of the piece **after** rotation. The artwork itself (`pieceWidth` × `pieceLength`) is
centred in that box and turned `rotation` degrees clockwise. `locked: true` marks a piece the user pinned.

In true-shape mode the transparent part of a piece's box may extend past the page edge; its silhouette never does.

### Validating and reusing a document

```js
import { validateDocument, nestingDocumentSchema } from "@inedit/nesting-ui";

const problems = validateDocument(receivedDocument); // [] when valid, else [{ path, message }]
```

`validateDocument` checks the structure and the consistency: every copy placed exactly once, placements pointing to
existing items, pieces on the page. `nestingDocumentSchema` is the JSON Schema (draft 2020-12), for validators in
other languages. Inèdit Connect applies the same checks before it builds a PDF.

### Nesting without the editor

The nesting itself is available without any user interface, in the browser or in Node, through `@inedit/nesting-core`
(also re-exported by `@inedit/nesting-ui`):

```js
import { computeNesting, buildDocument } from "@inedit/nesting-core";

const input = {
  items: [{ ref: "logo", width: 20, length: 20, units: "cm", copies: 12 }],
  page: { width: 1.6, units: "m" },
  options: { mode: "rectangular", allowRotation: true, allowOrthogonalRotation: true, padding: 5, paddingUnits: "mm", bleed: 0, showCutLines: true },
};
const result = computeNesting(input);         // synchronous; may take up to timeBudgetMs
const nestingDocument = buildDocument(input, result);
```

For true-shape nesting without the editor, build each silhouette with `buildShapeMask({ data, width, height, channels })`
from decoded RGBA pixels and pass them as `shapes: { [ref]: mask }` in the input.

## 11. Generating the PDF with Inèdit Connect

### What you need

- An Inèdit Connect account with nesting enabled.
- An **access token** of an Inèdit Connect account. Either:
  - the token of a user logged in to Inèdit Connect, or
  - an **API token** created in Inèdit Connect (long-lived, meant for integrations).

The company the token belongs to owns the uploaded files and the PDFs; other companies cannot see them.

### Connecting the editor

```js
const editor = new NestingEditor("#nesting", {
  page: { width: 1.6, units: "m" },
  items,
  render: {
    baseUrl: "https://nreservice.inedit.com/api",
    getToken: async () => currentAccessToken(),
  },
});

const { downloadUrl, report } = await editor.generatePdf({ name: "Order 1234" });
window.open(downloadUrl);
```

| `render` field | Description |
|---|---|
| `baseUrl` | Inèdit Connect API URL, ending in `/api` (or your proxy's URL, below). |
| `getToken` | Returns the access token (or a promise of it). It is called before **every** request, so it can return a refreshed token. Omit it when a proxy adds the token. |
| `headers` | Extra headers for every request. |
| `pollIntervalMs` | Time between status checks. Default `2000`. |
| `uploadRemoteImages` | `true`: the browser downloads `https://` images and uploads them, instead of Inèdit Connect fetching the URLs. Use it when Inèdit Connect cannot reach your image URLs (intranet, signed URLs that expire soon). |

When `render` is set, the panel shows a "Generate PDF" button (control `"pdf"`) with progress and, once ready, a link.
You can also call `generatePdf()` from your own button and hide the panel's one.

### Where the token should live

The token gives access to the company's Inèdit Connect account. Choose the pattern that fits your application:

**A. An application where users log in to Inèdit Connect** (an internal tool, a back-office).
Pass the logged-in user's token through `getToken`.

**B. A public website** (a shop where customers prepare their own nests).
Never put an API token in the page: anyone could read it. Put it in your own backend and let the editor talk to a proxy:

```js
// Browser: no token, the proxy adds it.
render: { baseUrl: "https://shop.example.com/nesting-api" }
```

```js
// Your backend (Node + Express): forwards the three nesting calls and adds the API token.
import express from "express";

const CONNECT = "https://nreservice.inedit.com/api";
const app = express();

app.use("/nesting-api/nestings/render", async (request, response) => {
  // Add your own checks here: is this visitor allowed to print? How many PDFs today?
  const upstream = await fetch(`${CONNECT}/nestings/render${request.url === "/" ? "" : request.url}`, {
    method: request.method,
    headers: {
      Authorization: `Bearer ${process.env.INEDIT_CONNECT_API_TOKEN}`,
      ...(request.headers["content-type"] ? { "Content-Type": request.headers["content-type"] } : {}),
    },
    body: ["GET", "HEAD"].includes(request.method) ? undefined : request,
    duplex: "half",
  });
  response.status(upstream.status).type(upstream.headers.get("content-type") || "application/json");
  response.send(Buffer.from(await upstream.arrayBuffer()));
});
```

The proxy must not parse the request body (uploads are multipart), and it is where you limit who may generate PDFs.

### What happens when a PDF is requested

1. The editor uploads each item's `image` (`POST /nestings/render/files`), unless it is an `https://` URL that Inèdit Connect can download.
2. It sends the `NestingDocument` and the list of files (`POST /nestings/render`). Inèdit Connect validates the document and queues the job.
3. It polls the job (`GET /nestings/render/:id`) until it is `ready` or `error`, emitting `pdf-status` along the way.
4. When the job is `ready`, `generatePdf()` resolves with a signed `downloadUrl`.

`downloadUrl` is valid for **15 minutes**. The panel's download link fetches a fresh one when needed. If you keep the job id,
call `GET /nestings/render/:id` again later for a new link.

### The PDF

- One page, as wide as the page and as long as the nest plus the bleed at both ends. The start of the nest is at the top.
- Artwork in an optional-content layer **Print**; cut paths in a layer **CutContour**, stroked in a `CutContour` spot colour
  (when `showCutLines` is on).
- Raster artwork is embedded at its native resolution; PDF artwork stays vector; PSD spot channels become separate inks.

`report` (also in the `pdf-status` event) describes the result:

| Field | Meaning |
|---|---|
| `pageWidthPt`, `pageHeightPt` | Page size in points (1/72 in). |
| `maxDpi` | Highest native resolution among the placed images. |
| `inks` | Extra (spot) inks found in the artwork. |
| `colorModels` | Colour models of the artwork (`rgb`, `cmyk`, `gray`, `lab`, `devicen`, `pdf`). |
| `overlaps` | Pairs of pieces whose cut paths cross, e.g. `{ a: "Logo #1", b: "Logo #2" }`. They should be fixed before printing. |
| `warnings` | Things to check: a true-shape piece cut as a rectangle, a PDF without its own bleed… |

### Limits and retention

| | |
|---|---|
| Largest artwork file | 1 GB (uploaded or downloaded from a URL) |
| Pieces per nest | 5000 |
| Uploaded files and PDFs | kept 15 days, then deleted |
| Download links | valid 15 minutes |
| Artwork URLs | `http`/`https` only; addresses of Inèdit Connect's own network are refused |

PDFs are built one at a time, in the same queue as the nests saved in Inèdit Connect, so a job may wait for others.
A job that has not finished after 3 hours is reported as failed.

### Calling the endpoints directly

The three endpoints can be used without the editor, for example to print a document you stored earlier.
All need `Authorization: Bearer <token>` and return `{ "data": … }`; errors return `{ "message": "…" }` with a 4xx/5xx status.

```sh
# 1. Upload the artwork of each item
curl -H "Authorization: Bearer $TOKEN" -F "file=@logo.png" https://nreservice.inedit.com/api/nestings/render/files
# → 201 { "data": { "fileId": "5b0c…" } }

# 2. Queue the PDF
curl -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{ "name": "Order 1234", "document": { …NestingDocument… }, "files": { "logo": { "fileId": "5b0c…" }, "flag": { "url": "https://cdn.example.com/flag.png" } } }' \
  https://nreservice.inedit.com/api/nestings/render
# → 202 { "data": { "id": "9f1e…", "status": "queued", … } }

# 3. Poll until ready
curl -H "Authorization: Bearer $TOKEN" https://nreservice.inedit.com/api/nestings/render/9f1e…
# → 200 { "data": { "id": "9f1e…", "status": "ready", "error": null, "report": { … }, "downloadUrl": "https://…" } }
```

`files` must name an artwork for every `ref` that has placements.

### Cross-origin calls

The browser calls Inèdit Connect from your page's domain, so Inèdit Connect must allow it (CORS). Its `ORIGIN` setting
is `*` by default, which allows every site. If an installation restricts it, your site's origin has to be added.

## 12. Styling

The editor's look is plain CSS in `nesting.css`: classes prefixed with `inn-` and custom properties prefixed with `--inn-`.
There is no Shadow DOM, so your stylesheet applies directly. Load your overrides **after** `nesting.css`.

Set them on `.inn` (or any ancestor, scoped as you like):

#nesting .inn {

### Size and layout

The editor fills its element (`width: 100%; height: 100%`, minimum 420 px tall). When the editor itself is narrower than
760 px, whatever the window size, the panel moves under the canvas and the editor scrolls inside its box.

To start from scratch, do not load `nesting.css` and style the classes above yourself.

## 13. Languages and texts

The editor speaks **English** (`en`, the default), **Catalan** (`ca`) and **Spanish** (`es`). Italian (`it`) is also included.

### Choosing the language

```js
new NestingEditor("#nesting", { page, items, locale: "ca" });
```

- A region variant uses its language: `"ca-ES"`, `"es-AR"` and `"es_ES"` all work.
- An unknown code uses English. `editor.getLocale()` says which language is in use.
- Numbers follow the language: `0.223 m` in English, `0,223 m` in Catalan and Spanish (toolbar and rulers).
- The editor's root element gets a matching `lang` attribute.

### Switching while the editor is open

```js
languageSelect.addEventListener("change", () => editor.setLocale(languageSelect.value));
```

`setLocale` redraws the texts and keeps everything else: the nest, the selection, pinned pieces, the PDF status.
[`examples/basic`](../examples/basic) has a language selector that does this.

### Changing some texts

`messages` replaces texts of the chosen language by key. The rest stay as they are:

```js
new NestingEditor("#nesting", {
  page,
  locale: "es",
  messages: { generatePdf: "Enviar a imprimir", pageWidth: "Ancho del rollo" },
});
```

Texts can hold placeholders in braces (`{count}`, `{name}`, `{ref}`, `{url}`, `{dpi}`, `{inks}`) that the editor fills in; keep them
when you rewrite a text.
`getMessages("ca")` returns every text of a language, which is a convenient starting point; `getMessages("en")` lists every key.

### Adding a language from your page

`registerLocale` adds a language without changing the package. Call it before creating the editor (or before `setLocale`):

```js
import { registerLocale, NestingEditor } from "@inedit/nesting-ui";
// with the script tag: const { registerLocale, NestingEditor } = window.IneditNesting;

registerLocale("fr", {
  usedLength: "Longueur utilisée",
  utilization: "Utilisation",
  generatePdf: "Générer le PDF",
  // …any key of getMessages("en")
});

new NestingEditor("#nesting", { page, items, locale: "fr" });
```

Texts you leave out come from English, so a partial translation already works. To start from another language instead,
pass it as the base: `registerLocale("ca-valencia", { usedLength: "Llargària usada" }, { base: "ca" })`.
`availableLocales()` lists the languages known.

### What stays in English

- Messages written by Inèdit Connect: the reason a PDF failed when the server gives one (for example "Invalid token")
  and the warnings of the PDF report.
- Errors meant for developers, thrown when the editor is used wrongly (for example `NestingEditor: target element not found`).
- The `NestingDocument` and everything returned by the API: keys and values do not depend on the language.

## 14. Using it from React, Vue and other frameworks

The editor manages its own DOM inside the element you give it. In a framework, create it once when the element
is mounted, update it through its methods, and destroy it on unmount. Do not re-create it on every render.

### React

```jsx
import { useEffect, useRef } from "react";
import { NestingEditor } from "@inedit/nesting-ui";
import "@inedit/nesting-ui/nesting.css";

export function Nesting({ items, options, onChange }) {
  const element = useRef(null);
  const editor = useRef(null);

  useEffect(() => {
    editor.current = new NestingEditor(element.current, { page: { width: 1.6, units: "m" }, options, items });
    const stop = editor.current.on("change", ({ document }) => onChange?.(document));
    return () => {
      stop();
      editor.current.destroy();
    };
  }, []); // create once

  useEffect(() => void editor.current?.setItems(items), [items]);
  useEffect(() => editor.current?.setOptions(options), [options]);

  return <div ref={element} style={{ height: 700 }} />;
}
```

### Vue 3

Use the Vue component, `@inedit/nesting-vue`. It brings the editor along and loads its CSS:

```sh
npm install https://nreservice.inedit.com/api/static/nesting/0.1.2/inedit-nesting-vue-0.1.2.tgz
```

```vue
<script setup>
import { ref } from "vue";
import { NestingEditor } from "@inedit/nesting-vue";

const items = ref([{ ref: "logo", name: "Logo", image: "/images/logo.png", width: 20, units: "cm", copies: 10 }]);
const options = ref({ mode: "trueShape", padding: 5, paddingUnits: "mm" });
const nest = ref(null); // the NestingDocument
</script>

<template>
  <NestingEditor style="height: 700px" :page="{ width: 1.6, units: 'm' }" :items="items" :options="options" @change="document => (nest = document)" />
</template>
```

Props follow your state, events come back as Vue events, and a template ref gives `settled()`, `getDocument()`,
`generatePdf()` and the rest. **Everything about it is in [the Vue component's documentation](VUE.md)**, and
[`examples/vue`](../examples/vue) is a complete app.

Without the component, the same takes a few lines with the plain editor:

```vue
<template><div ref="element" style="height: 700px" /></template>

<script setup>
import { onBeforeUnmount, onMounted, ref, toRaw, watch } from "vue";
import { NestingEditor } from "@inedit/nesting-ui";
import "@inedit/nesting-ui/nesting.css";

const props = defineProps({ items: Array, options: Object });
const emit = defineEmits(["change"]);
const element = ref(null);
let editor = null;

onMounted(() => {
  editor = new NestingEditor(element.value, { page: { width: 1.6, units: "m" }, options: toRaw(props.options), items: toRaw(props.items) });
  editor.on("change", ({ document }) => emit("change", document));
});
watch(() => props.items, items => editor?.setItems(toRaw(items)));
watch(() => props.options, options => editor?.setOptions(toRaw(options)), { deep: true });
onBeforeUnmount(() => editor?.destroy());
</script>
```

Pass plain objects to the editor rather than reactive proxies (`toRaw()`). `File` and `Blob` images can be passed as they are.

### Anything else

The same three steps apply everywhere (Angular, Svelte, server-rendered pages): create on mount, call
`setItems` / `setOptions` / `setPage` when your data changes, `destroy()` on unmount.

## 15. The examples

### `examples/minimal`: fixed settings, the user only picks copies

[`examples/minimal`](../examples/minimal) is the smallest useful integration. Everything is set in one file,
[`config.js`](../examples/minimal/config.js): the Inèdit Connect URL and token, the page width, the nesting
parameters and the list of images (file name in `assets/`, size and starting copies). The page shows the nest
read-only (`ui: { panel: false, editable: false }`), a number of copies per image, and two buttons: Export PDF and Export JSON.

```sh
# put your images in examples/minimal/assets/ with the names listed in config.js, set the token, then
# serve the folder with any static web server, for example:
npx serve .             # then open http://localhost:3000/examples/minimal/
```

The page reads the images from `assets/`, which browsers block for pages opened as files (`file://`), so it needs a server.

Until an image exists it is drawn as a grey box with its configured size, and the PDF says which image is missing.

One detail worth copying from it: `setItems()` returns a promise, and `getDocument()` returns `null` while the new nest
is computed. A number field fires `change` when it loses focus, which happens when the user clicks Export, so the
export handlers wait for the pending `setItems()` before reading the document.

### `examples/basic`: the host page controls everything

[`examples/basic`](../examples/basic) is a plain HTML page that loads the script-tag bundle and shows every part of the
integration: its own item list with sizes and copies, its own parameter form (with the editor's panel reduced to the
placement order), JSON export, PDF generation with an API URL and token, an event log and CSS overrides.

```sh
npx serve .             # then open http://localhost:3000/examples/basic/
```

In the page, "Add sample items" adds three generated images; "Add images…" adds your own files. To try the PDF, fill in
your Inèdit Connect API URL (ending in `/api`) and an access token, then "Use these settings".


### `examples/vue`: a Vue 3 app

[`examples/vue`](../examples/vue) does with Vue what the two others do with plain JavaScript: the app keeps the
images, copies, roll width, spacing, rotation and language in its own state and passes them to the
[`<NestingEditor>` component](VUE.md) as props, with JSON and PDF export. It also lets the user add images from disk.
It needs Node.js: `npm install` and `npm run dev` in its folder (see its [README](../examples/vue/README.md)).

## 16. Troubleshooting

| Symptom | Cause and fix |
|---|---|
| The editor is invisible or flat | Its element has no height. Give it one (`height: 700px`, or a flex/grid layout that sizes it). |
| "… needs a width and a length" | The item has no size and the editor cannot work it out (image not loaded, or no `dpi`). Give `width` and/or `length`. |
| "… does not fit across the page" | The item is wider than the page in every allowed rotation. Widen the page or allow rotation. |
| True shape nests an item as a rectangle | The image is on another domain without CORS, has no transparent or uniform background, or is a format the browser cannot show (give `previewImage`). |
| A solid label loses its background in true shape | Its border is one uniform colour, treated as background. Add a margin or use rectangular mode. |
| No "Generate PDF" button | `render` is not set, or `ui.controls` does not include `"pdf"`. |
| PDF fails with "Invalid token" or "Authentication token is required" | `getToken` returns nothing, an expired token, or a token of another environment. |
| PDF fails with "… has no artwork" or "… was not found; upload it again" | An item has no `image`, or an uploaded file is older than 15 days. Generate again. |
| PDF fails for a URL image | Inèdit Connect cannot download it (private network, expired link, too large). Use `render.uploadRemoteImages: true`. |
| "Inèdit Connect could not be reached at …" (the console shows a CORS error) | Most often `baseUrl` lacks `/api`: without it the request reaches the web server, not the API, and the answer has no CORS headers. Otherwise the server is down, or its `ORIGIN` setting does not allow your site. |
| "… has no nesting PDF endpoints" | `baseUrl` is wrong, or that Inèdit Connect server runs a version without `/nestings/render`. |
| `report.overlaps` is not empty | Pinned pieces, or silhouettes traced differently from the print file, make cuts cross. Unpin or add padding, then generate again. |
| Pins and manual rotations disappeared | `setItems()` resets them by design, since the items may have changed. |
